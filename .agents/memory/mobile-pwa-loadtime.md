---
name: Mobile PWA cold-load performance
description: Conventions established for client load-time work — service worker caching split, static cache headers, route splitting, font loading, and the metrics beacon. Read before touching PWA load performance again.
---

- A `POST /api/client-metrics` endpoint (server/routes.ts) already exists and just `console.log`s a line prefixed `[client-metrics]`. The client side lives in `client/src/lib/perf-metrics.ts` and fires once on `window.load` via `navigator.sendBeacon`. Reuse this instead of adding a second beacon — a follow-up (persisting the readings instead of only logging them) is already tracked separately.
- The service worker (`client/public/service-worker.js`) treats `/assets/*` as cache-first because Vite content-hashes everything under that path at build time — the filename changes when the content does, so it's safe to cache forever. Everything else (HTML shell, `/api/*`, unhashed public files like manifest.json/icons) stays network-first/revalidating. Any new build output path must go through the same hashed/unhashed judgment call, not be added ad hoc.
- Static file serving (`server/vite.ts` `serveStatic`) mirrors this: `Cache-Control: public, max-age=31536000, immutable` only for paths containing `/assets/`, `no-cache` for everything else (including the SPA fallback `index.html`).
- **Why this split matters:** caching an unhashed file (index.html, manifest.json) as immutable would freeze deploys/PWA metadata for existing installs; not caching hashed `/assets/*` files defeats the point of content-hashing and forces a full re-download of the ~unchanged bundle on every cold open.
- Route/page components in `client/src/App.tsx` are all `React.lazy()` + `Suspense`, specifically so a renter's first load never pulls in admin-only page code (and vice versa). Any new top-level page added to the router must follow the same lazy-import pattern or it silently rejoins the eager bundle.
- Only Inter is an actually-used Google Font in this app (see tailwind.config.ts `fontFamily.sans`); `--font-mono`/`--font-serif` fall back to system fonts (Menlo/Georgia) and need no web font. `client/index.html` was previously loading ~30 unused Google Fonts families (leftover scaffold bloat) — check actual usage (`grep -r "font-mono\|font-serif"` and tailwind config) before assuming a big Google Fonts request is intentional.
